## 1. Verdict

Eleven commits since the last audit have closed 26 of 44 registered defects, several of them properly — not papered over. The FAT32 detection layer is now correct on all three platforms and covered by 41 tests. Filename hygiene exists as a real function with 33 tests. A hash-chained audit trail exists. CI runs the suite on 9 OS/interpreter combinations. The origin split between control and content planes is architecturally correct and reasoned better than most commercial code. The remediation was competent and honest: comments now document what the code *does* rather than what the author wished it did, and the CSP xfails are `strict=True` so they fail loudly when the gap closes.

That is the good news, and it is real. It does not change the disposition.

**The system remains non-procurable by all four target authorities.** Three findings are individually disqualifying, and all three are new — the prior audit did not contain them:

1. **`web.py` `loadDrives()` — unescaped filesystem-derived HTML in the credentialed console.** `d.path` from `/api/drives` is concatenated into `innerHTML` twice with no escaping, on an origin whose CSP still carries `script-src 'unsafe-inline'`. On POSIX the value is a directory name under `/media`, `/run/media`, `/mnt` or `/Volumes` — which an unprivileged local process can create. This is the exact defect class as the closed D5, surviving in a sink the fix did not sweep. It yields script execution with the session cookie in scope, hence authenticated `/api/download` with an operator-chosen `target` — an arbitrary-path write primitive. `loadStats()` has the same defect on `stats.bucket_path`.

2. **`/epubres` serves untrusted EPUB-internal markup with script enabled.** Verified empirically: an EPUB member returns `Content-Type: application/xhtml+xml`, no `Content-Disposition`, and CSP `default-src 'none'; script-src 'self' 'unsafe-inline'` — the permissive *plane default*, because unlike `/files` this route sets no policy of its own. The `sandbox` directive that makes the origin-split argument sound is applied at `/files` and nowhere else. A downloaded book executes script on the content origin, where `frame-src 'self'` lets it read the entire drive through same-origin frames.

3. **The audit chain is unkeyed and co-located with the data it attests.** `audit.py` computes plain `SHA-256(record ‖ prev_hash)` and writes it to `<bucket>/.kb_state/audit.log` on the same removable medium, writable by the same account that produces the records. Any adversary who can edit one record can recompute every subsequent hash in milliseconds. The module docstring asserts that editing "is detectable with **no trusted external copy**" — that is false against an adversary and true only against accidental corruption. NIST SP 800-53 **AU-9** requires protection of audit information *from* the entities it audits; this design provides none. The `expected_head` anchor is the right instinct but is optional, undocumented in the operator manual, and defended by no key.

Beyond these, the SBOM does not describe the artefact that ships — it omits the entire HTTP server stack (17 of 34 pinned packages, including FastAPI, Starlette, Pydantic and uvicorn, i.e. precisely the network attack surface), drifts on 5 versions, carries zero hashes and zero suppliers, and contains no Rust crate, no embedded CPython, no kiwix-tools and no WebView2 despite all four shipping on the stick. The conformance test passes because its hash-validation loop iterates over an empty list.

**Assessed maturity:** TRL 5, up from 4–5. The engineering quality of the *code* is now ahead of the engineering quality of the *evidence*, which is the inverse of what procurement rewards. Remaining gap to a submittable package: **5–8 phases**, of which perhaps six phases is code.

The *design instinct* — declare colours rather than `invert()` — is correct and the commit that made that change was right. The *claim* attached to it will not survive an evaluator with a spectroradiometer, and a falsified physical claim in a human-factors annex discredits the rest of the annex. Restate as: "monochrome green-dominant palette, WCAG contrast 11.5:1, dark-adaptation intent, **NVIS compatibility not claimed and not measured**." |
| **N26** | S3 | `archive_index.py:441–453` | `_gather()` iterates only top-level **directories**. Files sitting at the bucket root are never indexed, so a loose PDF dropped on the stick is invisible to `/api/search/local` with no indication why. |
| **N27** | S3 | `os_utils.nearest_existing` | `Path.resolve()` collapses symlinks before the ancestor walk, so a target beneath a symlink into another filesystem reports the *link target's* type, not the mount the write will land on. Rare, silent, and it is the FAT32 decision. |
| **N28** | S3 | `buckets/zim.py:659` | `_slice_suffix` overflows past `'z'` at index 676 (`chr(ord('a') + 676//26)` = `'{'`). Ceiling is 676 × 3900 MiB ≈ 2.48 TiB — beyond current media, but the failure mode is silent filename corruption rather than a refusal. One `if index > 675: raise`. |

## 4. Security architecture

### 4.1 The origin split — correct design, incomplete enrolment

The reasoning at `web.py:59–78` is the strongest single piece of security thinking in the codebase. Cookies are not port-scoped (RFC 6265 §8.5); therefore a second *port* is not a boundary; therefore the content plane binds a different *host*. That is right, and it is stated with the precision an evaluator wants.

The implementation enrols three of four content routes:

| Route | Origin | CSP | Disposition | Assessment |
|---|---|---|---|---|
| `/files/<file>` | content | `sandbox; default-src 'none'` | `attachment` for active types | Correct |
| `/files/<dir>` | content | plane default | — | KBB-generated markup, `html.escape` applied throughout `_render_library_listing`. Correct. |
| `/read` | content | plane default | — | KBB-generated; embeds untrusted media in a frame pointed at `/files`, which carries the sandbox. Correct. |
| **`/epubres/*`** | content | **plane default (script enabled)** | **none** | **N2 — untrusted bytes served under the trusted-page policy.** |
| `/wiki/*` | content | plane default | — | Proxied kiwix output, HTML rewritten and re-emitted under the *permissive* default. kiwix-serve output is derived from ZIM content, i.e. untrusted. Same class as N2, one degree removed. |

The plane's two populations — KBB's own pages and raw downloaded bytes — need two policies. The middleware implements the permissive one as the default and relies on individual handlers to opt into the strict one. **Invert this**: make `sandbox` the plane default and have the three KBB-generated routes opt *out* explicitly. Fail-safe defaults (Saltzer & Schroeder) is not a stylistic preference here; it is exactly the property whose absence produced N2.

Residual after N2 is fixed: **the content plane remains unauthenticated by design**, serving the entire bucket root — including `.kb_state/audit.log`, `sync_state.json`, `clone_manifest.json` and `.kb_env` — to any local process. The rationale ("it holds no authority to protect") is defensible for a public library and indefensible for a tool whose product is collected material. **AC-3 (access enforcement) and SC-4 (information in shared resources) are not satisfied.** The minimum viable fix is a second, separate ephemeral token for the content plane, delivered as a distinct `SameSite=Strict` cookie scoped to that host, plus exclusion of `.kb_state`/`.kb_env` from `/files` traversal.

### 4.2 Control plane

The token design is right in kind: `secrets.token_urlsafe(32)` (256 bits), `compare_digest` for both header and cookie paths, `HttpOnly` + `SameSite=Strict` + `path=/`. Gaps:

- Token has **no expiry and no rotation**; it lives for the process lifetime, and the cookie has no `Max-Age`, so it persists in the browser jar until the browser is closed.
- **No `Secure` flag** — correct for plaintext loopback, but it means the cookie transits any future TLS downgrade.
- **No authorisation tiers.** `/api/stats` (read telemetry) and `/api/clone` (write 90 GB to an arbitrary path) require the identical credential. AC-6 least privilege is not expressible.
- **No request logging suitable for audit** on the control plane — `audit.py` records acquisition, clone and read, but not authentication failures, not configuration changes actually performed through the API, and not `/api/download` target selection at the granularity AU-3 wants.
- **No rate limiting** on `/api/*`; the 401 path is unthrottled, so the token is brute-forceable at wire speed (256 bits makes this theoretical, but the control is absent, and an evaluator scores controls).

### 4.3 Cryptographic inventory

| Use | Algorithm | Assessment |
|---|---|---|
| Provisioning asset pinning | SHA-256 | FIPS 140-3 approved. Correct. But a hash pinned in a Python literal in the same repository that ships the code is an **integrity** check against a value the supplier controls — it is not **provenance**. |
| ZIM payload | MD5 (format-mandated) | Correctly marked `usedforsecurity=False` so FIPS-enforcing hosts do not raise; correctly documented. **Defensible only as a formal, written deviation** citing the OpenZIM container specification. It currently lives in a source comment. Write it up as a deviation record with the spec citation and the compensating control (N9's Metalink/`.sha256`). |
| Clone manifest | SHA-256 | Correct, and computed from the same buffers being written — no second read pass. Good engineering. |
| Audit chain | SHA-256, **unkeyed** | **N3.** Not an integrity control against an adversary. |
| Control-plane token | `secrets.token_urlsafe(32)` | Correct CSPRNG, correct width, constant-time comparison. |
| Signature verification | **none, anywhere** | No Authenticode check on WebView2 beyond a prose assertion, no GPG on kiwix-tools, no Sigstore on python-build-standalone, no signature on the Xapian wheel, no signature on `Launch_KBB.exe`, no signature on the SBOM, no signed commits or tags. |
| Data at rest | **none** | N24. |
| Data in transit (local) | **none** (plaintext HTTP on loopback) | Defensible on loopback; not defensible the moment `--host` is used (D19). |

There is no crypto-module inventory document, no FIPS 140-3 boundary statement, no key-management plan, and no algorithm-agility position. Each of these is a named artefact in every one of the four target processes.

## 5. Mathematics, resilience, scalability

### 5.1 State layer

The complexity annotations are now **honest** — `usb.py:111–121` states Θ(N²) aggregate plainly and names the remedy (append-only journal with compaction). That is a real improvement in evidence quality and no improvement at all in behaviour. Measured shape, unchanged:

- `mark_item_completed`: read file → `json.loads` → mutate → `json.dumps` → `fsync` → `os.replace`. Θ(S) per call, S ∝ N. Aggregate **Θ(N²)** bytes written.
- `is_item_completed`: full read + parse per call, invoked once per item in `_process_item`. Aggregate **Θ(N²)**.
- `audit.record`: full read + per-line parse per append (**N4**). Aggregate **Θ(N²)**, and this one is on the `/read` request path.

Three quadratic loops on flash media. At N = 500 items with a 60 KB state document this is ~15 GB of rewrite; at N = 5,000 it is ~1.5 TB, which will exhaust the write endurance of a consumer stick. The remedy is identical for all three and already written down: append-only journal, one `fsync` per record, in-memory head and in-memory `set`, compaction on clean shutdown, replay on start.

### 5.2 FAT32 split geometry

`FAT32_CHUNK_LIMIT = 3900 × 1024² = 4,089,446,400 B` against a ceiling of 4,294,967,295 B — a 196 MiB margin, conservative and correct. Slice boundaries are deterministic constants, so slice *k* always covers the same byte range across runs; that is what makes `_get_split_progress` safe despite never truncating stale slices, and it is the right property to have chosen.

`_update_hash`'s three-way branch is correct for the straddling case:

```
checksum_start = total_size − 16
bytes_after ≤ checksum_start          → update(chunk)             # wholly before
bytes_before ≥ checksum_start         → skip                      # wholly inside trailer
otherwise                             → update(chunk[:checksum_start − bytes_before])
```

Verified by 42 tests including boundary cases. Sound.

Defects around it: the fail-open detection (**N8**), the orchestrator's mismatched threshold (**N7**), the suffix overflow (**N28**), and — unaddressed since the first audit — **FAT32's 32 KB cluster geometry is never modelled**. On an Archive.org library of many small files, slack is 15–40 % of nominal capacity; every free-space computation in the codebase compares raw bytes to raw bytes. `check_capacity` would be the place to model it, and `check_capacity` is not called.

### 5.3 Concurrency and failure

- Four daemon threads: content-plane uvicorn, `_boot_kiwix`, index rebuild, clone. All swallow exceptions into module-level status dicts and none are joined. A clone that raises leaves `_STATUS["state"]` sticky and `is_running()` false — recoverable, but the UI polls a dict with no liveness proof.
- `KIWIX_PROCESS`, `KIWIX_CLIENT`, `BUCKET`, `JOBS` are module globals mutated from multiple threads without synchronisation. `JOBS` is dict-mutation only, so CPython's GIL saves it; that is an accident, not a design.
- The kiwix bring-up is the most carefully engineered part of the runtime: non-blocking boot off the startup path, a 5-minute bind budget, `EADDRINUSE` detection with port advance, a distinct `indexing` phase before `ready`, and index rebuild deferred until after kiwix settles so the two do not contend for the drive. The reasoning in the comments matches the code. This is good work.
- `backend_child.kill()` on Tauri `Exit` is a hard kill. With `STATE_FLUSH_INTERVAL = 100 MiB`, up to 100 MiB of transfer progress and any in-flight `.part` slices are orphaned. Documented as safe on the strength of atomic state writes — which D11 establishes do not hold on FAT32. Send a signal, wait, then kill.

### 5.4 Scalability envelope

| Dimension | Practical ceiling | Binding constraint |
|---|---|---|
| Items per bucket | ~10³ | Θ(N²) state layer (§5.1) |
| Audit records | ~10⁴ | Θ(N²) append (N4) |
| Indexed files | ~10⁵ | `rebuild()` materialises all paths; no incremental path |
| ZIM slices | 676 | `_slice_suffix` overflow (N28) |
| Concurrent operators | **1** | Module-global `BUCKET`, single process token, no session model |
| Kiwix catalogue queue | ~10³ entries | `KiwixQueue.build()` is O(N² log N): `max()` + filter + `sort` + `list.remove` per iteration |

The product is architected for one operator and one stick. That is a legitimate design point and should be **stated as a limit** rather than left to be discovered — "single-operator, single-volume, ≤10³ items" is a specification an evaluator can accept; silence about it is a specification they will test and fail.

### 6.2 Five Eyes (US-led: DoD / DISA / CISA)

- **NIST SP 800-53 Rev 5 / 800-171**: AC-3, AC-6, AU-9, SC-4, SC-8, SC-13, SC-28, SI-10 all unsatisfied or partial. AU-2/3/12 are *implemented* — the audit module is real work — but AU-9 negates their evidentiary value (N3).
- **CMMC 2.0 Level 2** (110 practices from 800-171) requires a POA&M and an SSP. Neither exists. The `AUDIT_*.md` documents are the raw material for a POA&M and should be converted into that format explicitly — it is the artefact an assessor reads.
- **EO 14028 / OMB M-22-18 / M-23-16**: self-attestation requires a conformant SBOM and secure-development attestation. N5 blocks the SBOM; the SLSA provenance in `publish.yml` is a genuine asset and should be foregrounded — it puts the project at **SLSA Build L2** for the PyPI artefact already, which is more than most submissions. The launcher binary has no equivalent.
- **DISA STIG / WDAC / AppLocker**: an unsigned `Launch_KBB.exe` will not execute on a compliant workstation. This is not a scoring deduction; it is a hard stop at first contact.
- **Removable-media policy**: DoD has banned unencrypted removable media since the 2008 `agent.btz` incident (Operation Buckshot Yankee, USSTRATCOM CTO 08-001, never rescinded). A plaintext USB knowledge stick is categorically non-compliant regardless of every other property. **N24 is the single highest-value item in this document for the US path.**
- **UK NCSC / Australian ASD Essential Eight**: application control (unsigned binary) and the ISM's removable-media encryption controls fail identically.

### 6.3 France (SGDSN / ANSSI)

- **CSPN** (Certification de Sécurité de Premier Niveau) is the realistic target: fixed cost, 8 steps of evaluator effort, well suited to a product this size. It requires a **cible de sécurité** (security target) naming assets, threats, hypotheses and security functions — the material exists in the two audit documents but has never been written in that form.
- ANSSI's *Recommandations de sécurité relatives aux supports amovibles* mandate encryption of removable media carrying sensitive data (N24) and a documented decontamination path for ingested content. KBB's threat surface is *precisely* content ingestion from an untrusted network onto media that crosses a boundary — this is the ANSSI use case, and the product currently performs no sanitisation, no format validation, and no CDR (content disarm and reconstruction) on ingest.
- **Cryptographic sovereignty**: ANSSI expects an inventory with a French-approved or ANSSI-qualified position. MD5 will be questioned. It is defensible with the OpenZIM citation *as a written deviation with a compensating control* (N9's Metalink SHA-256) and indefensible as a comment.
- Favourable factors: the codebase is auditable French-authored work with no telemetry, no cloud dependency, and no foreign SaaS in the runtime path. `Diffusion Restreinte` handling would additionally require ANSSI-qualified disk encryption (e.g. a qualified product for the volume) rather than anything KBB implements itself — which is the right architecture: **do not build crypto, integrate a qualified module**.
- **SecNumCloud is not applicable** (no hosting). Do not claim it.

### 6.4 Türkiye (MİT / SSB)

- **TSE / TS ISO/IEC 15408 (Common Criteria)** via a Turkish licensed lab (OKTEM/TÜBİTAK BİLGEM). EAL2 is achievable for a product of this size and is the appropriate target; EAL4 is not, without a formal design decomposition that does not exist.
- **Millî Teknoloji / localisation expectations**: an SSB acquisition will ask about source availability and local build capability. CC0-1.0 licensing is a strong position here — full source, no restrictions, locally buildable. This is a genuine competitive advantage and should be led with.
- TÜBİTAK BİLGEM cryptographic-module expectations apply to N24's eventual encryption layer; plan to integrate rather than implement.
- Turkish-language UI is absent. The `.lang-btn` CSS class exists with no i18n behind it — a hollow affordance is worse than none. Full `gettext` extraction is required, and the console's inline-HTML-in-Python-string-literal construction (`web.py`, ~1,400 lines of markup in string constants) makes extraction materially harder than it needs to be. This argues for the template-engine refactor on procurement grounds, not aesthetic ones.

### 6.5 NATO ("NATO-green" — NU to NATO RESTRICTED)

- **NIAPC** (NATO Information Assurance Product Catalogue) listing requires either a CC certificate or a national approval that NATO recognises. CSPN (§6.3) is the shortest route and would serve France and NATO from one evaluation. **Sequence CSPN first.**
- **AC/35-D/2004 and AC/35-D/2005** govern INFOSEC and media handling. Removable media at NATO RESTRICTED and above requires approved encryption and a registered, accountable handling procedure. N24 again.
- **STANAG 4774 / 4778** (confidentiality metadata labelling and binding). KBB has **no classification labelling model at all** — no per-item label, no label binding, no label propagation through clone or export. For a knowledge-distribution tool this is a first-class functional gap, not a compliance checkbox: a stick that mixes material of different provenance with no label cannot be handled under NATO rules. Implementing 4774 labels bound with 4778 to each acquired item, propagated through `clone_manifest.json` and the audit chain, would be a **differentiating capability** rather than a cost.
- **Cross-domain guarding**: any transfer between security domains requires an approved guard. KBB should be positioned explicitly as a **low-side collection and distribution tool**, never as a guard. State this in the security target; ambiguity here fails evaluations.
- Favourable: the offline-autonomous, no-callback, no-telemetry architecture is exactly right for disconnected NATO operations, and the deliberate loopback-only binding is a good starting posture.

### 6.6 What the project already has that is worth points

Do not under-sell these; they are unusual in a submission of this size.

1. **SLSA build provenance** on PyPI artefacts via OIDC trusted publishing with SHA-pinned actions and a job that resolves every pin against the GitHub API. That last job is better practice than most enterprise pipelines.
2. **A real audit-event model** (AU-2/AU-3/AU-12) with a defensible event taxonomy and honest documentation of its identity limitation.
3. **Cross-platform CI** on 9 combinations with a clean-clone precondition assertion.
4. **331 tests**, including 41 on filesystem detection, 42 on hash-window arithmetic and 33 on filename sanitisation — the three subsystems where correctness is hardest to eyeball.
5. **`xfail(strict=True)` on known gaps.** This is the single most credible thing in the repository: it encodes the unfixed defect as a test that will fail when it is fixed, so the register cannot silently rot. Say so explicitly in any submission.
6. **CC0-1.0.** Full source, no encumbrance, locally buildable — directly answers the sovereignty question every one of the four authorities asks.

## 8. What to keep, unchanged

The temptation in a report of this length is to conclude that the architecture needs replacing. It does not.

The bucket/engine ABC is a clean two-axis abstraction. The lazy-import discipline is correct and measured. The ZIM verification implements the container specification properly, including the FIPS-survivable MD5 treatment. The split geometry is deterministic and its resume logic is sound. The origin-split reasoning is better than most commercial code. The kiwix bring-up sequencing — non-blocking, phased, contention-aware — is careful engineering. The clone path now verifies, manifests and refuses to report a partial copy as success. The ergonomic instincts are real: determinate progress everywhere, named recovery actions, no dead states, keyboard-only operation, and a night optic built by declaring colours rather than inverting a document.

And the comments are, as of this commit, *honest*. `check_capacity` says it is not a FAT32 guard. `usb.py` says the operation is Θ(N²). `zim.py` says `os.replace` is not atomic on FAT32. The CSP gap is an `xfail(strict=True)` with a measured description of the work remaining. That change in evidentiary posture between the two audits is worth more to a procurement conversation than any three of the code fixes, because it is the property an evaluator cannot verify by reading and must instead take on the project's demonstrated character.

The gap to procurement is not architectural. It is **provenance, encryption, and completeness of evidence** — three workstreams, none of which requires rewriting what is already there.
