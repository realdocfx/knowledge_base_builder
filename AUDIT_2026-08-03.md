## 1. Verdict

Since `b410068` the project has closed four of the five hardest findings from the last audit and has begun signing commits. **N1** (unescaped filesystem-derived HTML in the credentialed console) is closed by applying the existing `escAttr`/`escHtml` helpers at both sinks. **N2** (`/epubres` serving untrusted EPUB markup with script enabled) is closed the *right* way — by inverting the content-plane default to `sandbox` and making the permissive policy an explicit per-route opt-out, which is the Saltzer & Schroeder fix rather than a spot patch; I confirmed this empirically at four routes. **N11** (unbounded `Retry-After`) is closed with a clamp, a warning and jitter. **N18** (`pip install .[web]` failing everywhere because of `xapian-bindings`) is closed by splitting the extra. The tri-modal rework — Mode A now loop-mounts the *same* `kbb_guest.img` that Mode C boots, over a tmpfs overlay — is the correct architecture and removes an entire class of drift by construction.

That is real progress, and the engineering judgement behind it is above the median for this class of software.

**The system remains non-procurable by all four target authorities**, and the reason has shifted. It is no longer principally a code-quality problem. Three items are individually disqualifying and all three are unchanged since 2026-07-29:

1. **No data-at-rest protection anywhere** (N24). A plaintext removable volume carrying collected material is categorically non-compliant under USSTRATCOM CTO 08-001 (US), the ANSSI *supports amovibles* recommendations (FR), and AC/35-D/2005 (NATO), regardless of every other property of the software. This is an unbuilt capability, not a defect, and it is the highest-value single item in this document.
2. **The audit chain is unkeyed and stored inside the medium it attests** (N3). `audit.py` computes plain `SHA-256(record ‖ prev_hash)` into `<bucket>/.kb_state/audit.log`, writable by the same account that produces the records. NIST SP 800-53 **AU-9** requires protection of audit information *from the entities it audits*; the design provides none, and the module docstring still claims detection "with no trusted external copy", which is true only against accidental corruption.
3. **Nothing that ships is signed.** `tauri.conf.json` still carries `"windows": []` — no Authenticode, no MSI signing (D10). An unsigned `Launch_KBB.exe` does not execute on a WDAC/AppLocker-enforced workstation; that is a hard stop at first contact, not a scoring deduction.

Beyond those, this audit adds **twelve new findings**, of which three are operationally significant and were verifiable in minutes:

- **P2 (S1)** — the "virgin stick" (`runtime`) clone is **silently incomplete for Modes A and C**. `cloning._RUNTIME_ITEMS` was never updated for the guest-image rework: it copies `EFI/`, `qemu/`, `boot/` and both sandbox launchers but **omits `kbb_guest.img`, `vmlinuz-kbb`, `initramfs-kbb`, `initramfs-kbb-baremetal`, `kbb_drivegen.ps1` and `kbb_mediagen.py`**. The clone reports `state: done`. Reproduced end to end (§4.1).
- **P3 (S1)** — the guest image, which *is* the shipping artefact for Modes A and C, is built by `pip install --break-system-packages --target … "/work[web]"` with **no `--require-hashes`, no `--no-index`, no pinning**. Every supply-chain control the project enforces on `.kb_env` is absent from the artefact that two of three modes actually boot. The supply-chain test suite inspects only `cli._install_portable_packages` and therefore cannot see this.
- **P4 (S2)** — `requirements.txt`, the hash-pinned closure, is **missing three declared dependencies**: `pypdf` (a `pyproject` core dependency), `pymupdf` (`[web]`) and `pycdlib` (`[sandbox]`). Consequence on a stick provisioned by `kb-builder portable`: no server-side PDF rendering (the WebKitGTK fix does not ship), no media ISO (non-ZIM content invisible in Mode C), degraded PDF body-text indexing.

**Assessed maturity: TRL 5**, unchanged. The *code* continues to improve faster than the *evidence*, which is the inverse of what procurement rewards. Remaining gap to a submittable package: **5–7 phases**, of which roughly two are code and the rest are artefacts that do not exist yet (security target, SSP/POA&M, crypto boundary statement, classification-labelling model, independent assessment).

| **P8** | **S2** | `web.py` content plane | **The content plane remains wholly unauthenticated and serves the bucket root.** Re-confirmed: `enforce_api_auth` is registered on `app` only; `content_app` has no equivalent. ## 4. Architecture

### 4.1 Tri-modal deployment — right idea, one broken edge

The decision to have Mode A loop-mount the *same* `kbb_guest.img` that Mode C direct-kernel-boots is the most valuable structural change since the last audit. Two execution contexts, one userspace, one artefact, one place to be wrong. The bare-metal initramfs (`baremetal_init_script`) is competently written: it polls for USB enumeration rather than assuming it, creates `/dev/loop0` explicitly because devtmpfs only provides `loop-control`, stacks a tmpfs upperdir so the appliance is amnesic exactly as `snapshot=on` makes Mode C, carries the stick into the new root by `mount --move` so the loop's backing file stays live, and emits `KBB-BAREMETAL-*` markers a log can be asserted on. The failure path drops to a shell instead of hanging. This is good work.

Three things spoil the edges:

- **P2** — the `runtime` clone does not carry the guest image, so the "duplicate a virgin stick" workflow produces a Mode-B-only drive that still advertises Mode A and Mode C launchers.
- **P11** — nothing boots the guest in the configuration that ships.
- **P7** — the `library/archive/` layout the whole design assumes is never produced by the tool.

The evolution recorded in the `VVFAT_*` constants deserves note as *evidence*, not just as code. Three measured limits are documented with the exact QEMU error text: the 2 GiB per-file ceiling (stricter than FAT32's own 4 GiB), the FAT16-style root entry cap, and finally the fixed ~516 MB synthesised volume that ended the approach. Recording the dead end and *why* it is dead is what lets a reviewer trust the file-backed-SCSI design that replaced it. Keep this discipline.

### 4.2 Origin split — the fix landed, and landed correctly

The reasoning at `web.py:59–78` was already the strongest security thinking in the codebase; the correction since is that the *default* is now safe. Verified live:

| Route | CSP applied | Disposition | Assessment |
|---|---|---|---|
| `/files/<file>` | `sandbox; default-src 'none'` | `attachment` for `.html`/`.svg`, `inline` for the reader set | Correct |
| `/files/<dir>` | `CONTENT_TRUSTED_CSP` (explicit) | — | KBB markup, `html.escape` throughout |
| `/read` | `CONTENT_TRUSTED_CSP` (explicit) | — | KBB markup; media embedded via `/files` |
| `/epubres/*` | **plane default = `sandbox`** | none | **N2 closed** |
| `/wiki/*` | `CONTENT_WIKI_CSP` (explicit) | — | Reasoned opt-out for kiwix's search XHR and form |
| `/pdf-page` | plane default | — | PNG only, correct |

`/epubres` still sets no `Content-Disposition`; with `sandbox` + `nosniff` that is now defence-in-depth rather than a hole, but adding `attachment` costs one line and closes the question.

Traversal was probed and holds at every route: `/files/../../etc/passwd` → 404, `/files/%2e%2e%2f…` → 403, `/read?path=../../../etc/passwd` → 403, `/documentation/view?name=../../../../etc/passwd` → 404. `_sandbox_file` correctly contains against the *narrowest* subtree the route owns rather than the stick root, and says why.

The unaddressed half is **P8**: the plane is correct about *isolation* and silent about *access*.

### 4.3 Control plane

Token design remains right in kind — `secrets.token_urlsafe(32)`, `compare_digest` on both paths, `HttpOnly` + `SameSite=Strict`, exchange of a one-shot `?t=` for a cookie. Gaps unchanged: no expiry, no rotation, no `Max-Age`; **no authorisation tiers** (`/api/stats` and `/api/clone` require the identical credential, so AC-6 least privilege is not expressible); no rate limiting on the 401 path; and the ungated surface is wider than it looks — `/`, `/docs`, `/openapi.json`, `/documentation`, `/documentation/view` and `/assets/*` all answer without a token, which matters the moment `--host 0.0.0.0` is used (D19).

## 5. Portability and OS-independence

**Strong.** `os_utils.py` is the best module in the repository and reads like it was written by someone who had been bitten: `normalise_fs_type` maps `vfat`/`msdos`/`fat`/`fat16` → `FAT32` and `exfat` → `EXFAT` *before* any `fat` test, with the ordering hazard called out inline; `_best_mountpoint` selects the **longest** matching mountpoint, because first-match returns `/` for everything and a stick under `/media` then looks like ext4; `_unescape_mount_field` decodes `\040` so a volume labelled `FIELD STICK` matches; macOS uses `mount(8)` rather than `df -T`, because `-T` on macOS takes a *type filter list*, not a path; Windows uses `GetVolumeInformationW`, not the ANSI variant. 41 tests. `get_fs_type` never raises, by contract, with a test that proves it.

## 6. USB / FAT32 logic

The split machinery is arithmetically sound and I re-derived it against the new constant.

- `FAT32_CHUNK_LIMIT = 1900 × 1024² = 1,992,294,400 B`. Against the vvfat ceiling `0x7FFFFFFF = 2,147,483,647` that leaves 155,189,247 B (≈148 MiB) of headroom; against FAT32's 4,294,967,295 B it leaves 2.3 GiB. Conservative, correct, and the reason for the tighter of the two is documented with the exact QEMU error.
- `VVFAT_MAX_FILE_BYTES = 2 × 1024³ = 2,147,483,648` is **one byte above** the limit it models (`> 0x7FFFFFFF`). Harmless today because no vvfat drive is ever emitted, but it is a constant that documents a limit incorrectly.
- `_update_hash`'s three-way branch is correct for the straddling case and is covered by 42 boundary tests:
  `bytes_after ≤ total−16 → update(chunk)`; `bytes_before ≥ total−16 → skip`; otherwise `update(chunk[:total−16−bytes_before])`.
- Slice boundaries are deterministic constants, so slice *k* always covers the same byte range across runs. That is what makes `_get_split_progress` safe despite never truncating stale slices — a good property, deliberately chosen.
- `_get_split_progress` verifies each recorded slice against its on-disk size and truncates the verified prefix at the first mismatch. Correct.
- **`STATE_FLUSH_INTERVAL = 100 MiB`** unified across both write paths — a ~1000× reduction in fsync count on a 100 GB transfer versus the old 1 MiB single-file cadence. This is the right kind of fix: one named constant, both paths, a test that asserts they agree.

**Defects around it:** the fail-open detection (**N8**), the exact-4-GiB orchestrator boundary (**N7**), the halved suffix ceiling (**N28**), the missing 206 assertion and unbounded write (**P5**), and — unaddressed across all three audits — **FAT32 cluster geometry is never modelled**. On a 32 KB-cluster volume holding an Archive.org library of many small files, slack is 15–40 % of nominal capacity; every free-space computation in the codebase compares raw bytes to raw bytes. `check_capacity` is the natural home and `check_capacity` is still not called from the ZIM path (its docstring says so plainly, which is honest and is not a fix).

## 7. Mathematics

Beyond the split geometry (§6), three areas:

**Ranking (`archive_index`).** The two-tier bm25 construction is genuinely clever and correctly reasoned: evaluating `bm25()` twice, once with the `content` column weighted `0.0`, makes a body-only match come out at exactly `0.0` while any name/metadata match comes out negative, so `ORDER BY (name_score = 0.0) ASC, score ASC` produces a strict tier ordering with relevance inside each tier. The weight vectors are length-checked against the column tuple by construction. `_fts_query` correctly extracts word tokens and wraps them as quoted prefix terms, then tries AND before OR — which is the right fallback order. `_deslug` handles CamelCase and snake_case so `gramsci` matches `AntonioGramsciSelections`. This is the best-reasoned mathematics in the project.

**Queue scoring (`wiki_orchestrator`).** See **P9**. Unanchored substring matching, an inverted similarity for the untagged case, seeding-parity-dependent alternation, arbitrary full-snapshot selection, and O(N² log N) construction. The module also carries the product's most consequential naming error: `VitalArticlesIndex` implies Wikipedia's Vital Articles list, and there is no such list in the code.

**Colorimetry.** See **N25**. The WCAG ratios quoted in the manual are correctly computed — I re-derived them — but they are legibility ratios presented as though they bounded emission, and the 520–555 nm claim is false for the specified hex colours on any RGB panel.

## 8. Resilience and scalability

### 8.1 Complexity, measured

| Operation | Per call | Aggregate over N | Note |
|---|---|---|---|
| `mark_item_completed` | Θ(S) read+parse+serialise+fsync+rename | **Θ(N²)** bytes written | Honestly annotated since D35; unchanged in behaviour |
| `is_item_completed` | Θ(S) full read + parse | **Θ(N²)** | Called once per item in `_process_item` |
| `audit.record` | Θ(N) read + per-line parse | **Θ(N²)** | N4 — and it is on the `/read` request path |
| `KiwixQueue.build` | Θ(N log N) per iteration | **Θ(N² log N)** | P9 |
| `ArchiveIndex.rebuild` | Θ(F) memory | Θ(F) | Materialises all paths; no incremental path (D38) |

Three quadratic loops on flash media. At N = 500 items with a 60 KB state document that is ≈15 GB of rewrite; at N = 5,000 it is ≈1.5 TB, which exhausts the write endurance of a consumer stick. The remedy is identical for all three and is already written down in the code comments: append-only journal, one fsync per record, in-memory head and in-memory `set`, compaction on clean shutdown, replay on start.

### 8.2 Failure behaviour

Good: the kiwix bring-up is the most carefully engineered runtime path in the product — non-blocking boot off the startup path, a 5-minute bind budget with `EADDRINUSE` detection and port advance, a distinct `indexing` phase before `ready`, and a portal that binds immediately regardless. The reasoning in the comments matches the code. The clone layer now refuses on insufficient capacity *before* copying, checkpoints the SQLite WAL so the copied `.db` is self-contained, fsyncs every file, writes a per-file SHA-256 manifest to the destination, and — correctly — reports a skipped file as `state="error"` with "the duplicate is INCOMPLETE" rather than as a footnote.

Weak:

- **P5** — resume can convert a completed multi-hour transfer into a destructive no-op.
- Four daemon threads (content uvicorn, `_boot_kiwix`, index rebuild, clone), none joined, all swallowing exceptions into module-level status dicts. `KIWIX_PROCESS`, `KIWIX_CLIENT`, `BUCKET` and `JOBS` are module globals mutated across threads with no synchronisation; `JOBS` survives on the GIL, which is an accident rather than a design.
- `backend_child.kill()` on Tauri `Exit` is a hard kill, justified by atomic state writes that D11 establishes do not hold on FAT32. Signal, wait, then kill.
- The guest kiosk supervisor restarts `cage` in an infinite loop with a 1 s sleep and no backoff and no failure ceiling; a UI that cannot start produces an unbounded restart storm writing to `/dev/console`.

### 8.3 Scalability envelope

| Dimension | Ceiling | Binding constraint |
|---|---|---|
| Items per bucket | ~10³ | Θ(N²) state layer |
| Audit records | ~10⁴ | Θ(N²) append (N4) |
| Indexed files | ~10⁵ | No incremental rebuild (D38) |
| ZIM slices per archive | **676** (≈1.22 TiB at 1900 MiB) | `_slice_suffix` overflow (N28) |
| ZIM slices per sandbox session | **512** | `KBB_MAX_ENTRIES` in `kbb_blkfuse.c` (P10) — and 256 SCSI targets before that |
| PDF pages per open document | unbounded ⇒ DoS | P6 |
| Concurrent operators | **1** | Module-global `BUCKET`, single process token, no session model |

The product is architected for one operator and one volume. That is a legitimate design point. **State it as a specification** — "single-operator, single-volume, ≤10³ items, ≤512 slices" is something an evaluator can accept; silence is something they will test and fail.

## 10. Ergonomics (MIL-STD-1472H)

The human-factors work is more serious than the label usually implies, and most of it is asserted by tests rather than by prose:

- **Keyboard-only operation** (§5.17): `/` focuses search, `Esc` closes the chromeless viewport, `1`–`9` jump to views — and the numbered targets are derived from `NAV_SECTIONS`, the single navigation source of truth, rather than a hand-maintained second list. The handler correctly declines to fire while the operator is typing. Seven tests.
- **No ambiguous dead states** (§5.17): the launcher pushes determinate progress (`phase, attempt N of M, elapsed`) to the boot screen and navigates only on a real HTTP 200, never on a bare socket accept — so `ERR_CONNECTION_REFUSED` cannot surface. `pollKiwix()` distinguishes `starting` / `indexing` / `ready` / `unavailable` rather than showing a spinner. Telemetry failure renders `LINK DOWN` with a retry counter rather than a frozen panel.
- **Recovery actions in error text** (§5.17.10.7): the strongest example is `zim.py:339` — a zero `Content-Length` produces a message that names the probable cause (chunked transfer encoding), the consequence, and the fix (use a release URL, not a redirector). This pattern is used consistently.
- **No duplicated navigation labels** (§5.17.1.3): the masthead deliberately does not restate `NAV_SECTIONS`, with the reason recorded inline.
- **Kiosk discipline** (Modes A/C): no getty on any TTY, `kernel.sysrq = 0` so Alt+SysRq cannot kill the compositor, `decorations(false)` because GTK client-side decorations gave the operator a working close button inside a kiosk, `disable_file_drop_handler()`. Each with the reason.
- **Night optic**: dual-optic tokens, applied pre-paint from `localStorage` so the bright frame never flashes, propagated to the content plane via `?optic=`/`?bright=` because it is a different origin with a different `localStorage`. The wiki is re-coloured by *declaration* rather than `invert()`, with raster media collapsed to luminance first — the reasoning is right and the tests enforce it.

**Where it falls down:**

- **N25** — the emission claim is physically false as written, the standard cited is the wrong one (MIL-STD-3009 governs NVIS), and no radiance measurement exists. A falsified physical claim in a human-factors annex discredits the whole annex.
- **P6** — the PDF reader can render itself unusable on the guest.
- **No internationalisation.** The `.lang-btn` CSS class exists with no i18n behind it. A hollow affordance is worse than none, and this is a direct procurement problem for the French and Turkish paths.
- **No accessibility position at all**: no ARIA roles on the dynamic panels, no focus management when the in-window viewport opens or closes, no `prefers-reduced-motion`, no stated WCAG conformance target. Section 508 / EN 301 549 are procurement gates in the US and EU respectively.
- The console is ~1,400 lines of HTML/CSS/JS inside Python string literals. That is what makes the CSP `unsafe-inline` gap expensive to close (D20), what makes `gettext` extraction hard, and what will make an accessibility pass hard. It is one refactor that unblocks three separate procurement requirements — which is the argument for doing it, not aesthetics.

### 11.3 France (SGDSN / ANSSI)

- **CSPN** is the realistic target: fixed cost, bounded evaluator effort, well suited to a product this size. It requires a **cible de sécurité** naming assets, threats, hypotheses and security functions. The material for it exists across three audit documents and has never been written in that form. This is the single most leveraged non-code artefact in the whole programme, because **CSPN also opens the NATO path** (§11.5).
- ANSSI's *Recommandations relatives aux supports amovibles* mandate encryption (N24) and a documented **decontamination path for ingested content**. KBB's threat surface is precisely content ingestion from an untrusted network onto media that crosses a boundary — this is the canonical ANSSI use case, and the product currently performs **no sanitisation, no format validation and no CDR** on ingest. Given that the product's entire purpose is to carry Archive.org and Kiwix material across a boundary, a CDR/validation stage is arguably a *functional* requirement, not only a compliance one.
- **Cryptographic sovereignty**: an inventory with an ANSSI-qualified position is expected. MD5 will be questioned. Defensible with the OpenZIM citation **as a written deviation with a compensating control** (N9's Metalink SHA-256), indefensible as a source comment.
- Favourable: auditable French-authored work, no telemetry, no cloud dependency, no foreign SaaS in the runtime path, and the *Diffusion Restreinte* answer is the right one — integrate an ANSSI-qualified volume-encryption product rather than building anything.

### 11.4 Türkiye (MİT / SSB)

- **TSE / TS ISO/IEC 15408 (Common Criteria)** through a licensed Turkish lab (TÜBİTAK BİLGEM / OKTEM). **EAL2** is the appropriate and achievable target for a product this size; EAL4 requires a formal design decomposition that does not exist.
- **CC0-1.0 licensing is a genuine competitive advantage here** and should be led with: full source, no encumbrance, locally buildable, locally auditable. That directly answers the *Millî Teknoloji* / localisation question an SSB acquisition will ask, and few competitors can.
- TÜBİTAK BİLGEM cryptographic-module expectations apply to N24's eventual encryption layer — again, integrate, do not implement.
- **Turkish-language UI is absent**, and the hollow `.lang-btn` is worse than nothing. `gettext` extraction is required, and the 1,400 lines of markup-in-Python-string-literals makes it materially harder than it needs to be (§10).

### 11.5 NATO ("NATO-green", NU → NATO RESTRICTED)

- **NIAPC** listing requires either a CC certificate or a national approval NATO recognises. **CSPN is the shortest route and serves France and NATO from one evaluation — sequence it first.**
- **AC/35-D/2004 and AC/35-D/2005** govern INFOSEC and media handling. Removable media at NATO RESTRICTED and above requires approved encryption and a registered, accountable handling procedure. N24 again, plus a handling procedure document that does not exist.
- **STANAG 4774 / 4778** (confidentiality metadata labelling and cryptographic binding). KBB has **no classification labelling model at all** — no per-item label, no binding, no propagation through clone, export or the audit chain. For a knowledge-*distribution* tool this is a first-class functional gap: a stick that mixes material of differing provenance with no label cannot be handled under NATO rules. Implementing 4774 labels bound per 4778 to each acquired item and propagated through `clone_manifest.json` and `audit.log` would be a **differentiating capability**, not a compliance cost — and the audit chain and clone manifest are already the right places to put it.
- **Position the product explicitly as a low-side collection and distribution tool, never as a cross-domain guard.** Ambiguity on this point fails evaluations; stating it plainly in the security target removes an entire line of questioning.
- Favourable: offline-autonomous, no callback, no telemetry, loopback-only by default, amnesic in Modes A and C. That posture is exactly right for disconnected operations and should be stated as a *designed* property with the evidence (tmpfs overlay, `snapshot=on`, `KBB_STATE_DIR` on tmpfs).

### 11.6 What is already worth points

Do not under-sell these; they are unusual at this scale.

1. SLSA Build L2 provenance with OIDC trusted publishing, SHA-pinned actions, and a job that resolves every pin against the API.
2. A real AU-2/AU-3/AU-12 audit-event model with a defensible taxonomy and an honest written statement of its identity limitation.
3. Cross-platform CI on 9 OS × interpreter combinations with a clean-clone precondition assertion.
4. 524 test outcomes concentrated on the three subsystems where correctness is hardest to eyeball.
5. `xfail(strict=True)` on known gaps — the most credible artefact in the repository.
6. CC0-1.0: full source, no encumbrance, locally buildable — answers the sovereignty question all four authorities ask.
7. Comments that record *measured* dead ends with the exact error text (vvfat, SDL-vs-GTK, Mesa's software-rendering refusal, `.bat` multi-line PowerShell). This is verification evidence in the codebase, and it is rare.

## 12. Remediation sequence

Ordered by **evidence value per unit effort**, not by severity alone.

### Phase 0 — hours, and nothing downstream is credible without it

1. **P1** — add `.gitattributes` (`* text=auto eol=lf`; `*.bat text eol=crlf`; `*.ps1 text eol=crlf`), run `git add --renormalize .`, commit once, sign it. Sign an annotated `v0.5.1` tag. **~1 hour.** Everything else in this list is unverifiable until the baseline is nameable.
2. **P2** — derive `_RUNTIME_ITEMS` from `cli.SANDBOX_INFRA_NAMES`; add a test that clones a simulated tri-modal stick in `runtime` mode and asserts every file `start_sandbox.bat` and `grub.cfg` reference is present on the destination. **~2 hours.**
3. **P4** — regenerate `requirements.in`/`requirements.txt` with `pip-compile --generate-hashes --extra web --extra sandbox`; add a test asserting the pinned set is a superset of every dependency declared in `pyproject.toml`. **~1 hour.**
4. **P5** — assert `206` on resume; cap the write loop at `total_size`; on mismatch preserve the slices and report rather than delete. **~2 hours.**
5. **D15 residue** — `timeout=` on `pull_snapshot_stream`; remove `--password` from argv in favour of an env var or a prompt. **~1 hour.**

### Phase 1 — one phase, evidence quality

6. **N5 + P3** — regenerate the SBOM from `requirements.txt` **with** extras and hashes, emit `supplier`, merge a `cargo-cyclonedx` document for the 389 crates, and add explicit components for CPython 3.13.5, kiwix-tools 3.8.2, WebView2 150.0.4078.96, QEMU and the Alpine base. Strengthen `test_sbom_conformance.py` so it asserts the component set is a **superset** of `requirements.txt` and that every component carries a hash — the current test cannot fail. Then apply `--require-hashes --no-index` to the guest-image build and checksum the `kiwix-tools` fetch, and add a supply-chain test that reads `sandbox.yml`, not only `cli.py`.
7. **N3** — HMAC-SHA-256 the audit chain under a key held off the medium; retain the plain hash as a secondary field; publish `head()` to a second location at every `CLONE_COMPLETE`; on clone, terminate the source chain and start a new genesis on the destination recording the source head as provenance (**N23**). Correct the docstring's detection claim. Cache the head in memory under the existing lock (**N4**).
8. **P11** — extend the CI boot to the shipping configuration: `snapshot=on`, both consoles, `kbb_port`, a synthetic ZIM attached over `virtio-scsi-pci` with a V2 manifest, and a media ISO — then assert `KBB-ZIM-MOUNTED`, `KBB-PORTAL-OK` and a successful `/files` fetch of a media file.

### Phase 2 — the gate

9. **N24** — integrate a validated at-rest encryption layer. Do not implement crypto. Produce: a key-management plan, a zeroisation procedure, an emergency-erase path, and a statement of what is and is not protected (the guest image and launchers must stay readable for boot; content, `.kb_state` and the index must not).
10. **D10** — code-sign `Launch_KBB.exe` and the MSI (`tauri.conf.json` `windows.certificateThumbprint` + timestamp URL + `digestAlgorithm`), notarise on macOS, publish detached signatures for `kbb_guest.img` and `sbom.json`. Tighten the launcher's own `security.csp` to remove `'unsafe-eval'`.
11. **P8** — token-gate the content plane with a distinct host-scoped cookie; exclude `.kb_state` and `.kb_env` from `/files`.

### Phase 3 — the artefacts that do not exist

12. **Cible de sécurité (CSPN)** — assets, threats, hypotheses, security functions, and the explicit statement that the product is a low-side tool and not a guard. This unlocks both FR and NATO.
13. **SSP + POA&M** — mechanically convert the three audit documents.
14. **Crypto boundary statement** — inventory, FIPS 140-3 position, the MD5 deviation as a formal record citing the OpenZIM container spec with N9's Metalink SHA-256 as the compensating control, and an algorithm-agility position.
15. **STANAG 4774/4778 labelling** — per-item label, cryptographic binding, propagation through clone and audit. Treat as a capability, not a checkbox.
16. **CDR / ingest validation** — format validation and disarm on acquisition. This is the ANSSI use case and, arguably, a functional requirement of the product.
17. **i18n (`gettext`) + accessibility pass** — both gated behind extracting the console from Python string literals; that refactor also closes the D20 CSP residue. One piece of work, three requirements.
18. **Independent security assessment** by a party that did not write the code.

## 13. What to keep, unchanged

`os_utils.py` in its entirety. The origin-split reasoning at `web.py:59–78` and the now-inverted CSP default. The `xfail(strict=True)` discipline. The `VVFAT_*` constants with their recorded dead ends. The clean-clone CI precondition and the action-pin resolution job.
